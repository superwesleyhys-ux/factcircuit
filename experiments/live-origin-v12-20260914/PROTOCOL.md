# V12: incremental source review with immutable receipts

This is a preregistered development retest after V11. The user requested that
unchanged information sources not undergo repeated review in the double loop.
It is not a new holdout or a prospective prediction trial. The same two raw
ScienceDaily news cases, factual claims and December 31, 2024 cutoff are retained.
Later outcomes are not loaded by the runner. Prior failures and costs remain
reported in the V8–V11 records.

## Policy change

Double-loop tracing defaults to incremental source review. Each immutable
eligible source version is decomposed once. New sources must supply explicit
cross-source relations and exact-evidence gap resolutions. Previous analyses,
origin findings and unresolved gaps remain intact; an arriving document never
automatically promotes a declared edge or closes an obligation. Repeat requests
and automatic upstream-arrival revisits are recorded as skipped.

Prior full source text is not resent to later decomposition calls. The fact
verifier receives each full source version once in its own stage, together with
previous verdicts and exact evidence records. Host quotation validation still
uses the complete original material. Missing details in a prior evidence record
remain missing; no model-memory completion is permitted. Source identity and
source reliability are separate questions.

Exact aliases with the same URL, content, issuer and historical-availability
metadata are represented by one selected version. Aliases are recorded as not
admitted. A changed content or metadata version is distinct and must be checked;
version-ID collisions fail before any cache reuse. Generic provenance callers
retain an explicit legacy reanalysis option; this experiment uses the new default.

The existing full news-research workflow and shared final assessment are retained.
The no-repeat requirement is measured within native decomposition and native
verification, separately. The two different stages and the common final forecast
can still each read the same source once. This is not a claim that a source occurs
only once across every prompt in the entire application.

## Runtime and accounting change

The journal deep-copies input packets/schemas at entry and model responses on
return. It writes blocked-dispatch records separately from actual model attempts.
The first failed model call prevents any further model dispatch in that arm;
there is no same-arm retry, fallback model, salvaged error-bearing output or
replacement prediction. The other registered arm/case may still execute.

Local CLI diagnostics now preserve the exact submitted stdin and schema in
private request receipts, plus partial stdout/stderr when available on timeout.
Public summaries contain hashes and counts, not raw private packets. A failed
call's measured usage is retained; missing usage stays unknown, never zero.
The local process is launched under an idle-sleep inhibitor for this run only.
This cannot guarantee network availability or prevent an intentional lid close.

## Matched comparison

Both arms use gpt-6-astra with low reasoning via local Codex CLI login. Inference
is remote. They start from the same frozen raw seed text and have the same host
archive/bibliography tools and maximum budgets: 36 actual model calls per case
and arm, 6 document attempts including the seed, 4 retrieval decisions and 2
bibliography lookups. Each lookup exposes at most 5 candidates and requires a
model selection. No installed skills, model web access, shell, apps, plugins,
multi-agent tools or API-key fallback are enabled inside model calls.

Archive retrieval uses eligible captured HTML at or before the cutoff, up to
5 MB decoded raw bytes and 1,000,000 text characters per source, 5 candidate
captures, 8 archived redirect hops and 60 seconds per fetch. The aggregate final
evidence limit is 1,000,000 characters, enforced without truncation. There is no
current-page or PDF fallback and no disabled TLS verification. Cached text enters
an arm only after that arm explicitly requests its URL. Failed requests remain
visible; later archive availability can differ from earlier rounds.

Modern bibliography metadata is identity-only locator information with a
pre-cutoff creation check. It is not historical evidence or a reconstruction of
2024 search. Source-context quotations and the fetched archived study must bind
before a bibliography edge is admitted. Both native endpoints must be admitted,
even when an earlier endpoint is represented by incremental metadata and its
accepted analysis. A catalog entry alone is insufficient.

## Success and prediction boundaries

A source trace passes only when the target original study is actually fetched
in full, the common final chain uses observed links or validated bibliography,
and the native trace independently reaches that original with valid exact bases,
no dropped unresolved source obligations and no native errors. A press release,
unvisited DOI or completed final JSON alone cannot pass. The post-run audit
checks complete raw/extracted-body hashes, title/DOI identity, methods/results,
exact spans, gap lifecycle and per-version native model-call counts. Supplementary
files and laboratory data are not claimed fetched unless independently checked.

The common final response separately reports underlying fact status, origin
chain, later major reliability-withdrawal risk by the end of 2026, and whether
intentional fabrication is established. Unresolved is not early fraud detection;
retraction is not automatically fabrication; ordinary risk does not prove truth.
Same forecasts will be reported as a tie. The repeatedly inspected two cases and
later model memory preclude unseen-holdout or clean prospective-accuracy claims.
All code, protocol, local-check records and seed hashes are frozen before dispatch.
